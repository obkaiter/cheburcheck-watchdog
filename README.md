# Cheburcheck Watchdog

Служба для Ubuntu и Debian, которая по расписанию проверяет публичные IPv4 и IPv6 через [Cheburcheck](https://cheburcheck.ru/kb/api). В журнал systemd попадают результат проверки по спискам блокировок, сводка ответов сетевых сканеров и ошибки API.

Автор: github.com/obkaiter

При поддержке BITWIRE.ME

## Установка

Нужны Ubuntu 22.04+ или Debian 11+ с работающим systemd, права `sudo` и доступ к GitHub и `cheburcheck.ru`. Установщик и команда управления устанавливают недостающие зависимости через `apt-get`.

```bash
curl -fsSL https://raw.githubusercontent.com/obkaiter/cheburcheck-watchdog/main/install.sh | sudo bash
sudo cheburcheck-watchdog
```

Для установки из локальной копии репозитория выполните `sudo bash ./install.sh --local` из её каталога. Установка регистрирует службу в systemd. Первый запуск службы выполняется из меню после настройки.

## Управление

Откройте `sudo cheburcheck-watchdog` в интерактивном терминале. Используйте стрелки ↑ и ↓ и Enter. В главном меню также можно набрать номер пункта и нажать Enter. Статус службы обновляется по данным systemd.

1. **Запустить watchdog**. Подтвердите запуск клавишей Enter. Если токен или список адресов ещё не настроены, меню предложит их заполнить. Watchdog начнёт проверку сразу и будет запускаться при загрузке сервера.
2. **Остановить watchdog**. Подтвердите действие клавишей Enter. Текущая проверка прервётся, расписание остановится, автозапуск отключится.
3. **API-токен Watchdog**. Введите токен Cheburcheck для публичных сканеров. Символы при вводе скрыты.
4. **Проверяемые IP-адреса**. Добавьте публичные IPv4 или IPv6. Чтобы удалить адрес, выберите его в списке. Удаление последнего адреса останавливает службу и отключает автозапуск.
5. **Период проверки**. Доступны интервалы в 1, 3, 6, 12, 24 и 48 часов, а также неделя. По умолчанию — 6 часов.
6. **Удалить Cheburcheck Watchdog**. Удаляет службу, команду, файлы приложения и настройки, включая токен. Существующие записи хранятся по правилам журнала systemd.
7. **Выход**. Закрывает меню.

Изменения настроек сразу применяются к работающей службе. Её перезапуск начинает новый цикл проверок.

## Проверки и журнал

Для каждого адреса Watchdog сначала запрашивает `/check`, а затем использует выданный контекст для `/probe/<id>`. Ответы сканеров собираются до события `done`. В журнале отдельно отмечаются неполные результаты и повторно использованные измерения. По документации Cheburcheck стандартный кеш измерений действует три часа.

Адреса в цикле проверяются последовательно с паузой в 5 секунд. Следующий цикл начинается через выбранный интервал после завершения текущего. При HTTP 429 текущий цикл прерывается. Если заголовок `Retry-After` требует более долгой паузы, используется указанное API время.

```bash
sudo journalctl -u cheburcheck-watchdog.service -n 100
sudo journalctl -u cheburcheck-watchdog.service -f
```

## Автообновление

При открытии меню Watchdog читает `VERSION` в выбранной ветке GitHub. Если версия выше установленной, Watchdog скачивает архив ветки, проверяет версию и обязательные файлы, устанавливает обновление и заново открывает меню. Работающая служба перезапускается, чтобы подхватить новый код. Токен, список адресов и период хранятся отдельно. При сбое проверки или загрузки открывается установленная версия.

Пропустить проверку обновлений для одного запуска можно так:

```bash
sudo CHEBURCHECK_WATCHDOG_SKIP_UPDATE=1 cheburcheck-watchdog
```

Установщик и автообновление используют `CHEBURCHECK_WATCHDOG_BRANCH`. По умолчанию выбрана ветка `main`. Для другой ветки задавайте переменную и при установке, и при последующих запусках `cheburcheck-watchdog`.

| Путь | Назначение |
| --- | --- |
| `/opt/cheburcheck-watchdog/` | Файлы установленного приложения |
| `/usr/local/bin/cheburcheck-watchdog` | Команда управления |
| `/etc/systemd/system/cheburcheck-watchdog.service` | Юнит systemd |
| `/etc/cheburcheck-watchdog/config.json` | Токен, IP-адреса и период проверки, файл с правами `0600` |
