# Работа с Cheburcheck Watchdog

- Проект предназначен для Ubuntu 22.04+ и Debian 11+ с systemd. Используйте Bash и стандартную библиотеку Python 3.9+.
- `install.sh` устанавливает приложение. `cheburcheck-watchdog` проверяет зависимости и обновления перед запуском меню. `lib/deploy.sh` отвечает за установку и обновление файлов, `menu.py` — за управление, `watchdog.py` — за конфигурацию и работу с API.
- Конфигурация в `/etc/cheburcheck-watchdog/config.json` доступна только root. systemd передаёт её службе через `LoadCredential`. Храните настройки отдельно от файлов приложения и не выводите токен в журнал, аргументы команд или сообщения об ошибке.
- При изменениях API сверяйтесь с [документацией Cheburcheck](https://cheburcheck.ru/kb/api). Проверяйте обработку `done`, неполных ответов SSE и HTTP 429. Используйте заглушку API для проверок, которые могут расходовать кредиты.
- При изменении меню сохраняйте навигацию стрелками и Enter, экраны описания перед действиями и отдельное меню для уже добавленного IP. Пример оформления — [RemnaSuper](https://github.com/obkaiter/RemnaSuper).
- Перед коммитом проверьте `bash -n` для скриптов и `python3 -m py_compile menu.py watchdog.py` для Python. Если меняется установка или служба, проверьте затронутые сценарии на Debian или Ubuntu с systemd либо явно укажите, какие проверки не удалось выполнить.
- Обновляйте `README.md`, если меняются команда установки, способ запуска, пользовательские возможности, переменные окружения или поведение автообновления.

## Коммиты и публикация

После каждой правки инкрементируйте версию ПО `VERSION` и создавайте один коммит с сообщением в формате `Версия <X>: <название правки>` (например, `Версия 6.16: обновить меню релея`) (где `<X>` новая версия) и сразу отправляйте его в upstream текущей ветки. Не выносите изменение `VERSION` в отдельный коммит: включайте его вместе с правкой при выпуске версии.
